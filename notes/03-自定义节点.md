## 核心机制（源码事实 + 已验证项）

1. 【源码事实 + 实测】**`nodeTypes` 查找与回退**：`NodeWrapper`（`components/NodeWrapper/index.tsx:55-62`）先取 `let nodeType = node.type || 'default'`，再查 `let NodeComponent = nodeTypes?.[nodeType] || builtinNodeTypes[nodeType]`。查不到时调用 `onError?.('003', errorMessages['error003'](nodeType))`，并把 `nodeType` 重置为 `'default'`、回退到 `nodeTypes?.['default'] || builtinNodeTypes.default`。因为内置 `DefaultNode` 只渲染 `data.label`，当自定义节点的 `data` 没有 `label` 字段时，回退渲染出来的是**空白无文字的默认方框**。
2. 【源码事实】**`NodeWrapper` 传给自定义组件的 `NodeProps`**：在 `<NodeComponent ... />`（`NodeWrapper/index.tsx:225-243`）处，库传入 `id`、`data`、`type`、`positionAbsoluteX`、`positionAbsoluteY`、`selected`、`selectable`、`draggable`、`deletable`、`connectable`（映射为 `isConnectable`）、` parentId`、`zIndex`、`dragging`、`dragHandle`、`width`、`height`、`sourcePosition`、`targetPosition`。自定义组件外层已被 `<NodeWrapper>` 的 `.react-flow__node` 容器包住并由库负责 `transform: translate(...)` 定位，自定义组件只管渲染卡片内部结构和 `<Handle />`。
3. 【源码事实】**为什么 `nodeTypes` 必须保持引用稳定**：`<NodeComponent>` 是 `NodeWrapper` 按 `nodeTypes[nodeType]` 取出的 React 组件引用。如果把 `const nodeTypes = { inspectorCard: ... }` 写在父组件函数体内且每轮渲染新建对象（更糟的是在里面内联定义组件函数），一旦组件引用变化，React 对账时会卸载旧子树、挂载新子树，导致节点内的 `<input>` 每次敲击更新 state 后立刻卸载重建并丢失焦点。
4. 【源码事实】**三个工具类名的默认名与拦截点**：
   - 默认值在 `container/ReactFlow/index.tsx:121-123`：`noDragClassName = 'nodrag'`、`noWheelClassName = 'nowheel'`、`noPanClassName = 'nopan'`。
   - `nodrag`：`system/src/xydrag/XYDrag.ts:406-414` 在 d3-drag 的 `.filter` 中判断 `(!noDragClassName || !hasSelector(target, \`.${noDragClassName}\`, domNode))`（`hasSelector` 使用 `element.closest` 沿 DOM 向上查到节点根容器为止）。匹配到 `.nodrag` 时 `.filter` 返回 `false`，d3-drag 根本不会启动该次节点拖拽。
   - `nowheel`：分两条链路拦截——（a）常规滚轮缩放在 `system/src/xypanzoom/filter.ts:65` 的 `createFilter` 中判断 `if (isWrappedWithClass(event, noWheelClassName) && isWheelEvent) return false;`；（b）开启 `panOnScroll` 时的滚轮平移在 `system/src/xypanzoom/eventhandler.ts:74` 的 `createPanOnScrollHandler` 开头判断 `if (isWrappedWithClass(event, noWheelClassName)) return false;`。两条链路都放行浏览器原生滚动，因此节点内部的 `overflow-y: auto` 列表可以自己滚动而不触发画布缩放或平移。
   - `nopan`：`system/src/xypanzoom/filter.ts:71` 判断 `if (isWrappedWithClass(event, noPanClassName) && ...) return false;`。此外，`NodeWrapper/index.tsx:190` 在 `isDraggable` 为真时已经给整个节点外层挂上了 `nopan`；当节点被设为不可拖动（`draggable: false`）但内部又有需要拖选文字的输入框时，给控件显式加 `nopan` 仍能防止拖选文字时带动整张画布平移。
5. 【源码事实】**`updateNodeData` 在受控流下的完整链路**：
   - `useReactFlow().updateNodeData(id, dataUpdate, options)`（`hooks/useReactFlow.ts:257-266`）内部调用同文件的 `updateNode`，默认 `options = { replace: false }` 会把新旧 `data` 做浅合并：`{ ...node, data: { ...node.data, ...nextData } }`（只传 `{ stepCount }` 不会冲掉 `title` 和 `notes`）。
   - `updateNode` 调用 `setNodes((prevNodes) => ...)`（`useReactFlow.ts:73, 96-111`），把更新函数推入 `batchContext.nodeQueue`。
   - `BatchProvider`（`components/BatchProvider/index.tsx:31-65`）消费队列得到新数组 `next`，再用 `getElementsDiffChanges({ items: next, lookup: nodeLookup })` 与当前 `nodeLookup` 比对：发现同一 `id` 的节点对象引用变了，就生成 `{ id, type: 'replace', item: nextNode }`，最后调用受控画布的 `onNodesChange(changes)`。
   - 父组件的 `useNodesState` 收到 `type: 'replace'` 后，由 `applyNodeChanges` 把新节点对象替换进 React state，完成受控闭环。

## 个人理解

1. **自定义节点的本质与职责边界**：自定义节点就是一个接收 `NodeProps<MyNodeType>` 的普通 React 组件。外层的绝对定位（`transform: translate(...)`）、尺寸测量、选中与拖拽事件绑定都由库的 `NodeWrapper` 包办；自定义组件自己只负责两件事——渲染卡片内部 UI，以及显式放置 `<Handle />`（不写 `<Handle />` 就无法连线）。
2. **为什么 `nodeTypes` 要写在组件外**：`NodeWrapper` 每次渲染都用 `nodeTypes[nodeType]` 取组件引用。如果 `nodeTypes` 或里面的组件函数在每次渲染时重新创建，React 会认为组件类型变了，直接销毁旧 DOM 并重新挂载，导致节点里的输入框失焦、内部临时状态丢失。
3. **工具类名（`nodrag` / `nowheel` / `nopan`）的拦截原理**：React Flow 用 d3-drag 和 d3-zoom 在节点容器与画布容器上监听指针和滚轮事件。内部放表单控件（`<input type="range">`、`<input type="text">`）或局部滚动框（`overflow-y: auto`）时，事件会冒泡到外层被 d3 抢走。加上 `nodrag` / `nowheel` / `nopan` 后，库在 d3 的 `.filter` 函数里用 `closest` 向上检查事件目标，命中类名就返回 `false` 放弃接管，把事件还给浏览器原生控件。
4. **受控流下 `updateNodeData` 为什么不破坏单向数据流**：在节点内部调 `updateNodeData(id, partialData)` 并不会绕过父组件的 `nodes` state 偷偷改 store，而是先浅合并生成新节点对象，再由 `BatchProvider` 的 `getElementsDiffChanges` 转换成一条 `{ id, type: 'replace', item }` 的 `NodeChange`，依然走父组件的 `onNodesChange` → `applyNodeChanges` 写回状态，和 T01 的受控流数据闭环完全统一。

## 问题记录

1. **未注册 `nodeTypes` 时为什么连线曾经绕圈，以及为什么高度不同时水平连线会斜？**
   - 【实测】起初未设置 `sourcePosition` / `targetPosition` 时，回退的内置 `default` 节点默认是上进（Top）下出（Bottom），横向摆放时连线必须从底部绕到顶部；改成 `sourcePosition: Position.Right`、`targetPosition: Position.Left` 并将自定义节点的 `<Handle>` 也设为左右后，方向才一致。
   - 【实测】即便都设为左右连接点，左边 `entry` 节点文字折成两行后高度大于右边空白回退框，而 `.react-flow__handle-left` / `-right` 默认是 `top: 50%`（按各自高度垂直居中），导致两个连接点不在同一水平线上，连线呈斜S形。在 `custom-nodes.css` 中将左右 Handle 固定为 `top: 20px` 后，不同高度的节点在相同 `y` 坐标下连接点严格水平对齐。
2. **`stepCount` 字段在练习里起什么作用？**
   - 它不是 React Flow 的内置属性，而是自定义节点 `data` 里的业务示例字段（绑定到 `<input type="range">` 滑块），专门用来验证两件事：（1）左右拖动滑块时靠 `nodrag` 阻止节点跟着跑；（2）调用 `updateNodeData(id, { stepCount })` 时只传部分字段，验证库内默认做 `{ ...node.data, ...nextData }` 浅合并而不会丢失 `title` 和 `notes`。
